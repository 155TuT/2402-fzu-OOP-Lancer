# 2402-fzu-OOP-Lancer-课程设计

<u>made with 155TuT</u>

这是一份初学者的课程设计，简单的实现了一个这样的流程：

## 流程

1. 识别工作目录下的（默认为draft.md）markdown草稿

2. 识别该.md草稿的文件名，yaml前页中的title和date（一个基本的使用github pages托管的博客，其生成的draft的yaml前页所包含的项）

3. 在询问后设置文章的标题，文件名，生成对应的资源文件夹，设置日期，时间，标签，摘要等

4. 按照上述所选项更新yaml前页

5. 在工作目录的父目录下寻找名为_post的子目录，将生成后的文章保存在里面

并实现了如下功能：

## 功能

1. 全自动流程，简明询问，标准化输入（所有定项输入都有输入检查，非定项输入都有无害化处理）
2. 自动识别打开文件时的日期与时间
3. 有标签历史使用列表（存放在运行目录下的config.json中）
4. 可简单识别markdown正文中的代码块并将代码种类填入标签中
5. 可调用deepseek的api来自动对文本生成摘要（需手动在运行目录下的config.json中配置api key）

因而有如下依赖：

## 依赖

1. 目前仅能在windows下运行，还未做linux环境的适配
2. 编译器版本需要最少支持c++17标准（std::filesystem最早在c++17中获得支持，c++2a作为实验性选项可能不生效，请确保自己的编译器为尽可能新的版本），并在这里给出本机编译指令`g++ -std=c++20 changeyaml.cpp -o changeyaml.exe -I"C:/msys64/mingw64/include" -L"C:/msys64/mingw64/lib" -lssl -lcrypto -lws2_32 -lcrypt3`

3. 需完整下载/_drafts/下的 httplib.h和json.hpp（简单调用api和使用json文件的环境依赖）
4. 需下载openssl库，推荐使用msys2（如无openssl库，httplib.h仅能创建http请求，在链接时会返回400错误码，需使用openssl库才能创建https链接）
5. 如在运行时遇到任何问题，可去作者主页[155TuT (155TuT)](https://github.com/155TuT)寻求帮助

目前项目的优点如下：

## 优点

1. 进行了较良好的封装，将默认选项与配置文件部分与markdown文件本体的逻辑处理解耦，较符合面向对象程序设计的思路与初衷
2. 使用了较多的try/catch/throw与cerr，对可预料的错误都进行了可视性报错并尽量弥补，代码的鲁棒性较高
3. 使用了较标准的工程流程、清晰的注释与权限控制，代码的规范性与可读性较高，便于和别人进行协作与对接
4. 内存计算较为清楚，所有变量的申请与文件的读入都在使用周期结束时做了释放与关闭，内存管理较为安全高效

同时，作为一份初学者的课程设计，也有如下的缺点是在有限的开发时间内在所难免的：

## 缺点

1. 两个类间的关系（继承）并未在一开始厘清，导致代码的逻辑略有混乱，虽做了封装且能稳定运行，但内部逻辑需要重构
2. 代码长度较长，未使用头文件和命名空间进行分割
3. 部分期望实现的功能并未实现，如：
   1. 使用正则表达式匹配完成对markdown中一级标题的识别与安全化处理（在github pages的通常流程中，一级标题不该出现在正文中，期望达到的效果为：如识别到一个一级标题则询问是否作为本文title，如识别到多个一级标题则自动下调所有标题等级）
   2. 对置顶等级的持久化设置（github pages中yaml前页给定的参数是数字越大则置顶等级越高，期望达到的效果为：和标签历史使用列表一样，对所有置顶过的文章采用持久化方法存储在列表中，自动按照置顶关系分配历史文件与现在文件的置顶参数）
   3. 还未学习Qt因而未做图形化界面或插件挂载，事实上本项目最开始的设想是作为插件直接挂载在Typora上监听文件更新后自动实现上述流程，然而因还未做学习而搁置

4. 因还未做学习而未使用更规范化的CMake工具链

## 总结

第一次的面向对象编程经历让我收获很多，选题的苦恼纠缠了大半个月，总算发现应当先找一个手边的项目先做起来，做的过程中再去发现问题，而不是一直等待，等待项目机会，等待学习完成。这次的课设制作给了我继续学习面向对象程序设计的动力，感谢老师给我这次机会，也感谢坚持学习与实践的自己。
